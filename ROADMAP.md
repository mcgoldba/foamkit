# FoamKit Roadmap

## Questions for the maintainer
None open.

## Decisions (2026-10-18, 2026-10-19)
- **Approved by maintainer:** the ranked order, the T-010 canonical name table and the `case.canonical(...)` accessor.
- **T-013 unit API:** parsed units go on a new `.units` attribute. Unit-annotated values come back typed instead of as strings; this is treated as a bug fix and gets a CHANGELOG note.
- **`FoamKitError`:** becomes an `Exception` subclass. For one release it inherits from both `SystemExit` and `Exception`, with a CHANGELOG deprecation notice; a runtime warning "when caught as SystemExit" is not possible in Python. The `fk` CLI keeps its message and exit code (T-017).
- **T-015:** option A, true original quoting. Only the 4 golden lines and 1 test expectation pinned in the ticket may change.
- **T-016:** unknown directives are kept verbatim with a one-time warning, tracked in `foamkit.types` and documented on a Sphinx page (T-018). Public names approved: `ofVerbatimDirective`, `OF_DIRECTIVES`, `DirectiveInfo`, `iterDirectives`.
- **T-005 rescoped (real-file check, 2026-10-19):**
  - Boxed ESI and foam-extend banners are already recognised, so they are pinned as characterization tests.
  - The bug part is only header-less `FoamFile` files.
  - Skipped files stay silent (no warning).
  - **One-line `FoamFile { ... }` (2026-10-19):** header-less files with a one-line block are not recognised for now and stay skipped, as on HEAD, because the parser cannot read them (`IndexError`, or the entries are lost). T-021 fixes the parser and widens the rule back.
- **T-006:** promoted to right after T-005. Headers are preserved byte-for-byte for Foundation, ESI and foam-extend, using real-file fixtures. The 3 `tests/golden/dicts/headers/*.txt` goldens (which currently record B3) are regenerated and reviewed deliberately. T-006 also fixes the same-line `FoamFile {` blank-line drift.
- **Writer formatting churn:** an unedited read → write must reproduce the file. Split into T-019 (whitespace) and T-020 (padding/layout).
- **foam-extend:** a third distribution, handled at the header and detection level. Name mapping is deferred. Supported-versions label approved (2026-10-19): "headers tested (4.1, 5.0), otherwise best-effort".
- **Order (2026-10-19):** T-015 goes next, ahead of T-017, by maintainer choice: stock Foundation 11 pitzDaily cannot load without it. Its error tests use `FoamKitError`, which stays valid under T-017's dual base. T-016 moves up because of the Foundation 14 `#print` evidence, and stays after T-017.
- **T-013 position (delegated to the coordinator, 2026-10-19):** stays after T-021. Real Foundation 13/14 pitzDaily files show no `[m/s]`-style units. The scope gains Foundation 14 named dimension sets (`[velocity]`).
- **Docs:**
  - Sphinx + MyST + Furo; the strict build is `sphinx-build -W --keep-going -b html docs docs/_build/html`.
  - Doc and README examples use `import foamkit.functions as fkf` / `import foamkit.types as fkt`.
- **Checks:** `mypy foamkit/`. The ruff/mypy baseline is recorded in T-002.
- **Python:** 3.9+, verified on 3.9.23 and 3.14; CI tests 3.9 and 3.12.
- **Release tags:** `v` prefix. Commitizen `tag_format = "v$version"` already matches; only the README needs fixing (T-003).
- **OpenFOAM support:**
  - Tested: Foundation 11-14 and ESI v2412, v2506, v2512, v2606.
  - Older releases are best-effort.
  - Detection order: override, then case banner, then environment.
  - Canonical names follow Foundation 14, mapped through one data table; writes keep the case's native names.
- **CHANGELOG.md is generated by commitizen** (`update_changelog_on_bump = true`). Tickets ask for a `fix:` commit whose body describes the user-visible change, never a hand-written CHANGELOG entry.
- **CLI user errors never show a traceback (maintainer principle, 2026-10-20).** Bad arguments, running a command in an invalid directory, or a missing `fk init` cache print one clean `ERROR:` line and exit non-zero. This applies to every `fk` subcommand and to all future CLI work. In particular, `fk edit` with no cache exits 1 instead of opening a console with `case = None` (T-023).
- **`userMsg` output is literal (2026-10-20).** Messages are never interpreted as rich markup, and the ERROR level always raises `FoamKitError`, whatever the text (T-025).
- **T-024 approved (2026-10-20):** delete `_interpretUnitsAndConvert` with no alias or stub.
- **T-016 split (maintainer-approved, 2026-10-21)** after the real-tutorial directive inventory (Foundation 11-14, ESI v2412-v2606; the table is in the plan doc).
  - T-016 keeps the verbatim framework (`ofVerbatimDirective`, `OF_DIRECTIVES`, `iterDirectives`), unknown-directive handling, and the single-line directives `#print`, `#remove`, `#inputMode`, `#calcInclude`, `#message`, `#codeBlock`, `#endCodeBlock` and `#codeInclude`. Its goal is that stock Foundation 14 pitzDaily loads.
  - Split out: T-026 (`#if`/`#ifeq`/`#else`/`#endif`), T-027 (value-position `#calc`/`#neg`), T-028 (`#codeDict`/`#word`), T-029 (`#includeModel`/`#includeConstraint`).
  - Non-directive blockers found in real files: T-030 (scoped `$` references), T-031 (block comments), T-032 (number formatting), T-033 (`#codeStream` writer).
- **T-034 (2026-10-21), a T-025 follow-up:** escape C1 and bidi controls in `userMsg`; `str(FoamKitError)` must never raise.
- **Fixtures** come from real files only. Source URLs are in `docs/plans/openfoam-compatibility.md`, under References.
- **`bin/` scripts:** deleted by the maintainer.

## Current state
- The core init → cache → load → edit → write path is tested on Linux and Windows CI. Headers round-trip verbatim for Foundation, ESI and foam-extend (T-006).
- Real files (2026-10-19): stock pitzDaily for Foundation 11 loads since T-015. **Foundation 14 still fails** (`#print`, T-016). Foundation 12/13 and ESI v2606 headers are fine.
- Real-tutorial inventory (2026-10-21), load failures by frequency:
  - value-position `#calc`/`#neg`: 100+ Foundation 13/14 files (T-027);
  - `#if`/`#ifeq` blocks: Foundation 13/14 `fvSchemes`, ESI (T-026);
  - scoped `$` references (T-030);
  - `#includeConstraint` (T-029);
  - block comments (T-031);
  - `#remove`/`#print`/other single-line directives (T-016).
- Other gaps:
  - `#codeStream` grows on every write (T-033); numbers are reformatted (T-032);
  - writer whitespace churn (T-019, T-020);
  - one-line `FoamFile { ... }` (T-021);
  - one-line sub-dicts (`p { type probes; }`) raise `IndexError`, so the whole case fails (T-022);
  - Foundation 14 named dimension sets read as strings (T-013).
- `fk init` / `write` / `plot` / `edit` on a non-case path crash with a traceback, or open a console with no case, instead of printing a clean `ERROR:` (T-023).
- `userMsg` does not escape C1 or bidi control characters, and `str(FoamKitError(42))` raises (T-034).
- `_interpretUnitsAndConvert` is dead code that fails on every call (T-024).
- There is no docs site, and the README has broken examples.

## Next (ranked)
**In progress:** T-016 verbatim directive framework and single-line directives (#23, narrowed 2026-10-21).

1. **T-016** (M): stock Foundation 14 pitzDaily loads, and the other directive tickets build on its type and registry.
2. **T-027** value-position `#calc`/`#neg` (S, #38): the most widespread load failure, in 100+ files per Foundation 13/14 release, mostly `blockMeshDict`.
3. **T-026** `#if`/`#ifeq` blocks (M, #37): blocks Foundation 13/14 `fvSchemes` (for example `cylinder`) and ESI dictionaries. It is less widespread than T-027.
4. **T-030** scoped `$` references (S, #41): a load failure in the stock Foundation 14 `cylinder` `fvSolution` and in ESI field files.
5. **T-029** `#includeModel`/`#includeConstraint` (S, #40): 7-13 Foundation `fvConstraints` files fail per release. It reuses T-015's design.
6. **T-023** `fk` user errors never show a traceback (S, #32): user-facing, but those commands already exit 1, so real-file load failures come first.
7. **T-031** block comments (S, #42): comments are lost, or ESI `blockMeshDict` files fail to load.

After these, the order is T-033 → T-019 → T-021 → T-022 → T-013 → T-034 → T-032 → T-028 → T-003 → T-024 → T-001 → T-007 → T-020 → T-018 → T-008 → T-010 → T-009 → T-011 → T-012 → T-014 (see `docs/plans/openfoam-compatibility.md`).
- T-033 is next because the file grows on every write.
- T-021 and T-022 were not seen in the real-tutorial inventory, so they drop below the files that fail today.
- T-028 affects only 3 files.
- T-024 can be picked up any time.
- T-020 follows T-007, so it can use T-007's test cases as its corpus.

## Deferred
- **Removing `SystemExit` from `FoamKitError`:** the release after T-017 ships.
- **Narrowing the 13 bare `except:` handlers:** they swallow `FoamKitError`, `KeyboardInterrupt` and real bugs. A ticket is proposed for **after T-016 and T-022**, which rewrite the same parser paths. Sites and proposed shape are under Known gaps in `docs/plans/openfoam-compatibility.md`.
- **foam-extend name mapping (T-010) and full foam-extend case fixtures:** only if users need them.
- **API reference:** after T-010 stabilises the API. Use autodoc2 or an env-clean autodoc (see T-001 risks).
- **Repo-wide `ruff format` and a zero-finding lint gate:** after the bug-fix tickets above, as one dedicated diff. Until then CI (`ci.yml`) only blocks new findings above the T-002 baseline.
- **Console aliases `pf`/`pt` → `fkf`/`fkt`:** a code ticket with a deprecation path, after T-003.
- **Real-OpenFOAM CI, write-side canonical helpers, case conversion, interpreting verbatim directives (backlog on the T-018 page), tutorials, hosting, versioned docs:** these need the work above first.
