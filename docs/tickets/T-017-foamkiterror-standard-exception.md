# T-017: `FoamKitError` becomes a standard `Exception` (with a one-release transition)

- **Type:** code (owner: `tester` first, then `implementer`)
- **Size:** S. If the `sys.exit()` cleanup grows, split it off as T-017b.

## Goal
Library callers can handle FoamKit errors with ordinary `except Exception` handlers, and an uncaught error in a script shows a normal traceback instead of silently exiting. The `fk` CLI keeps its current message and exit status.

## Today
- `class FoamKitError(SystemExit)` at `foamkit/__init__.py:34`, with `code = 1`.
- `userMsg(msg, "ERROR")` (`:123-148`) prints `ERROR: msg` (or logs it at DEBUG level) and raises `FoamKitError(msg)`. **`userMsg` itself does not need to change.**
- `tests/test_config.py:71-74` pins `err.value.code == 1` and `isinstance(err.value, SystemExit)`.

## Transition (verified feasible on Python 3.14, 2026-10-18)
A class that inherits from both bases works:

```python
class FoamKitError(SystemExit, Exception): ...
```

It is caught by `except Exception` **and** by `except SystemExit`, keeps `.code`, and when uncaught still exits with status 1. The tester re-checks this on Python 3.9 in CI.

- **Release N (this ticket):**
  - `FoamKitError(SystemExit, Exception)`;
  - the commit body states the deprecation, and a docstring note says the `SystemExit` base will be removed in the next minor release. CHANGELOG.md is generated by commitizen, so it is not hand-edited;
  - the CLI is changed to stop relying on `SystemExit` (see below).
- **Release N+1 (follow-up, not this ticket):** `FoamKitError(Exception)`.

**A DeprecationWarning "when caught as SystemExit" is not feasible.** Python gives the exception no hook that tells it which `except` clause caught it. The closest proxy would warn when `.code` is read (only `SystemExit` handlers do that), but the interpreter's own exit path also reads it, so the warning would fire on normal CLI exits. **The best available path:**
- the dual base for one release;
- a deprecation notice in the commit body (CHANGELOG.md is generated from commits by commitizen and is not hand-edited);
- a module-level note in the `FoamKitError` docstring.

No runtime warning is added, because warning on every raise would be noise for every caller.

## CLI
- `foamkit/__main__.py:main()` wraps the command dispatch (`commands[addArgs[0]]()`) in `except FoamKitError as e`. It exits with status 1 and prints the same text as today.
- Today the text comes from `userMsg` before the raise, so the handler must not print it a second time. A `FoamKitError` raised directly, without `userMsg`, prints `ERROR: <msg>` once.
- **Add a test first** (`tests/test_cli.py`, subprocess, like `tests/test_regressions.py:215`). It pins the exit code and stdout of an `fk` command that fails through `userMsg`, for example `fk init` on a folder that is not a case. Start it with today's output, and keep it unchanged after the change.

## Audit of code relying on `SystemExit` semantics (2026-10-18)
- **`except SystemExit`:** none in `foamkit/`.
- **`except Exception`:** two places, both re-raise. `foamkit/types/__init__.py:4056` and `foamkit/functions/load.py:173` keep the same behaviour.
- **Bare `except:` (already catch `SystemExit`, so unchanged by this ticket):**
  - `foamkit/types/__init__.py:452, 4866, 4891, 4898, 4904, 4910, 4937, 5646, 5685`;
  - `foamkit/functions/dictUtil.py:224, 282, 504`;
  - `foamkit/functions/_unitDecoder.py:63`.

  They already swallow `FoamKitError`, and also `KeyboardInterrupt`. List them as a follow-up and do not change them here.
- **Library `sys.exit()` on error paths:** these exit with **status 0** and no exception, so callers cannot catch them. Convert them to `userMsg(..., "ERROR")`, which is in scope because it is the same error contract:
  - `foamkit/functions/dictUtil.py:549` (invalid OpenFOAM file);
  - `foamkit/functions/readDict.py:45` (not a dictionary);
  - `foamkit/functions/_interpretUnitsAndConvert.py:60` (invalid obj).
  - `foamkit/functions/load.py:144` is unreachable after `userMsg(..., "ERROR")`; remove it.
- `foamkit/__main__.py:52` (`sys.exit()` after printing help) is CLI code. Leave it.
- `foamkit/commandline/_iPython_env.py:23-25` overrides the IPython `exit` repr. It is unrelated; leave it.

## Out of scope
- Removing the `SystemExit` base (release N+1 follow-up)
- Rewriting the bare `except:` handlers
- New exception subclasses

## Acceptance criteria
- [ ] The new CLI exit test passes before and after the change, with the same stdout and exit code 1.
- [ ] `FoamKitError` is an instance of both `Exception` and `SystemExit`. `pytest.raises(Exception)` catches `userMsg("x", "ERROR")`. `tests/test_config.py:71-74` still passes, and a new assertion checks `isinstance(err.value, Exception)`.
- [ ] The three library `sys.exit()` calls raise `FoamKitError` instead, each with a test. `load.py:144` is removed.
- [ ] There is a `fix:` commit whose body describes the user-visible change: the `SystemExit` base deprecation and the `sys.exit()` → `FoamKitError` conversions. The `FoamKitError` docstring states the plan. CHANGELOG.md is not hand-edited.
- [ ] `pytest -q` passes on 3.9 and 3.12. `ruff` and `mypy foamkit/` show no new findings compared with the T-002 baseline.

## Risks
- **Behaviour change for callers:** code with a broad `except Exception:` around FoamKit calls will now catch errors that used to end the process. That is the purpose of the change, and the commit body says so.
- **Silent swallowing:** the `sys.exit()` → `FoamKitError` conversions make some errors catchable by the existing bare `except:` blocks, which may swallow them. The tester checks that each converted path is not inside a bare `except:`.
- **Python 3.9:** the dual-base class layout must be verified in CI.

## Ranking rationale
**Order changed by the maintainer (2026-10-19):** T-015 → **T-017** → T-016. T-015 goes first because stock Foundation 11 pitzDaily cannot load without it. Its error-path tests use `pytest.raises(FoamKitError)`, which stays valid under the dual-base class, so nothing needs rewriting after this ticket. The reasons below still apply to T-016, which comes after this ticket.
- **New raise paths:** both of those tickets add new `FoamKitError` raise paths (unbounded directives, unbalanced parentheses). With this ticket first, their error tests are written once against the final semantics.
- **CLI pin:** the CLI exit test captures today's behaviour before the parser starts failing differently.
- **Not removed by T-016:** even after T-016, any remaining parse error ends the caller's process.
- **Small cost:** it is S and independent, so it delays T-016 by one short session.
